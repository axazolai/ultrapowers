```

/plugin install ultrapowers@ultrapowers
```

Репозиторий сам себе маркетплейс, поэтому свежей машине не нужна git-аутентификация.

## Три ветки — три разные сущности

У них нет общего предка (orphan-корни), потому что слияние между ними никогда не является верной
операцией.

| ветка | что хранит | кто правит |
|---|---|---|
| `original` | дерево апстрима дословно — по коммиту на релиз, с тегом `upstream/<версия>` | только запись нового релиза апстрима |
| `patch` | карта плагина, преобразование переименования, собственные файлы форка и наши дельты | руками, осознанно |
| `main` | сгенерированный плагин | никогда руками |

`original` существует, чтобы у вопроса «из какой базы это собрано» был ответ, который не может
сдвинуться. `upstream/main` можно перезаписать force-push'ем; тег в нашем собственном
репозитории под нами изменить нельзя.

## Что переносится, а что нет

`transform/inventory.json` классифицирует каждый путь апстрима как `tracked` (переносится,
переименовывается, отслеживается на изменения) или `ignored` (сознательно не поставляется) — с
записанной причиной на каждое правило. Из 180 файлов апстрима 6.2.0 отслеживается 51: манифест
плагина, хук `SessionStart`, скиллы и `LICENSE`. Остальное — другие харнессы, собственный
тестовый набор апстрима, его документы и релизная оснастка.

Правила предлагают, манифест подтверждает. Путь, который появился у апстрима, но отсутствует в
манифесте, считается **новым**, и сборка отказывается работать, пока его не классифицирует
человек. Одни только globs молча приняли бы всё, что апстрим добавит; голый список файлов был бы
неподдерживаемым. Вместе они дают и гейт, и поддерживаемость.

## Что лежит в ветке `patch`

- `transform/config.json` — записанная база (`originalTag` и хеш её дерева), подстановки
  переименования, защищённая строка, ревизия, из которой выводится версия сборки, атрибуция,
  которую сборка проверяет, и пороги отказа.
- `transform/inventory.json` — манифест классификации, правила, которые его предлагают, и список
  `forkOwned`: файлы, которые форк пишет целиком, а не патчит. Сейчас их семь — два README,
  манифест маркетплейса, `.gitattributes`, аллокатор `phase-dir` и промпты
  summary-writer'а и верификации.
- `transform/deltas/NNN-*.patch` — тринадцать нумерованных изменений текста скиллов апстрима,
  применяемых по порядку. Что делает каждая — перечислено в README плагина.
- `transform/*.mjs` — движок (классификация, переименование, патчи, сборка) и его тесты.

Версия плагина **выводится**, а не патчится: `<версия апстрима>-up.<ревизия>` из `config.json`,
поэтому обновление апстрима не может оставить дельту, утверждающую устаревшую версию. Поднимайте
`version.revision`, когда изменился форк, а апстрим — нет.

## Пересборка

```
node transform/inventory.mjs check    # карта всё ещё описывает апстрим
node --test                           # преобразование всё ещё ведёт себя как задумано
node transform/build-cli.mjs check    # плагин всё ещё собирается, и ничего лишнего не выжило
node transform/build-cli.mjs commit   # записать результат в main
```

`build-cli.mjs` понимает ещё `emit <dir>` (выложить собранное дерево на диск), `tree`, `drift`
(является ли `main` в точности тем, что даёт свежая сборка?) и `facts` (машиночитаемый отчёт,
который анализирует `/up-update`).

Сборка **отказывается** работать — вместо того чтобы выпустить правдоподобно выглядящий сломанный
плагин — когда: путь апстрима не классифицирован или новый; дельта больше не применяется; имя
апстрима выжило где-то за пределами единственной защищённой строки; из собранного дерева пропала
атрибуция, которой требует лицензия.

`obsolete` сообщается, но не отказывает: дельта, чьё изменение апстрим с тех пор сделал сам, —
это решение, которое надо принять, а не ошибка. Мёртвые дельты — то, как форки накапливают груз,
из-за которого их в итоге бросают, поэтому о них сообщают на каждой сборке и удаляют осознанно.
